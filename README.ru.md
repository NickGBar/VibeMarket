# VibeMarket

[English](README.md) · **Русский**

Автономный маркет бесплатных приложений с открытым исходным кодом. Без рекламы, баннеров и трекеров. Часть OpenCraft Hub.

Сайт: https://nickgbar.github.io/VibeMarket/

Маркет работает без сервера и без модераторов в ежедневной работе. Сайт лежит на GitHub Pages. Разработчики подают заявки через GitHub, сообщество голосует реакциями, а робот в GitHub Actions по правилам из `rules.json` публикует, переносит и снимает приложения.

## Как приложение попадает в маркет

1. Автор добавляет своему репозиторию тему (topic) `vibemarket` и выпускает релиз. Тему может поставить только тот, у кого есть права на репозиторий, поэтому чужой проект подать не получится.
2. В разделе «Песочница» автор нажимает «Предложить приложение» и заполняет форму. Форма открывает на GitHub уже заполненную заявку на языке сайта, автор отмечает три подтверждения и отправляет её.
3. Робот проверяет заявку за несколько минут и отвечает комментарием на языке формы. Если что-то не так, автор правит заявку, и робот проверяет её снова.
4. Сообщество голосует 👍 или 👎 под заявкой. Голосование идёт 7 дней, и пока оно идёт, заявку видно на полке «Идёт голосование» на сайте.
5. Если голосов хватило, робот добавляет приложение в песочницу, закрывает заявку и публикует сайт.
6. Через 90 дней приложение с 500 звёздами и без жалоб робот переносит в обычную категорию на главной. Пометка «Стороннее» при этом остаётся.

Все числа берутся из `rules.json`.

## Правила

| Ключ | Что значит | Сейчас |
| --- | --- | --- |
| `repo.minAgeDays` | Минимальный возраст репозитория, дней | 30 |
| `repo.requireRelease` | Нужен хотя бы один релиз | да |
| `repo.requireTopic` | Тема, которая доказывает права на репозиторий | `vibemarket` |
| `repo.allowForks` | Принимать форки | нет |
| `repo.licenses` | Разрешённые лицензии (SPDX) | MIT, Apache-2.0, GPL и другие открытые |
| `voting.days` | Длительность голосования, дней | 7 |
| `voting.votesNeeded` | Сколько нужно 👍. Разница 👍 − вес×👎 тоже должна быть не меньше этого числа | 10 |
| `voting.downvoteWeight` | Вес одного 👎 | 2 |
| `voting.voterMinAgeDays` | Минимальный возраст аккаунта голосующего, дней | 90 |
| `promotion.minDays`, `promotion.minStars` | Когда переносить на главную | 90 дней, 500 звёзд |
| `reports.toHide` | Сколько жалоб от разных аккаунтов скрывают приложение | 3 |
| `limits.candidatesPerAuthor` | Сколько заявок одного автора может быть на голосовании одновременно | 3 |
| `scout.topics` | Темы GitHub, по которым ищет разведчик | `desktop-app`, `electron-app`, `tauri-app` и другие |
| `scout.minStars` | Сколько звёзд нужно находке | 1000 |
| `scout.releaseWithinDays` | Последний релиз не старше, дней | 365 |
| `scout.perRun` | Находок за один запуск | 5 |
| `scout.skip` | Репозитории, которые разведчик не предлагает | нет |

Голос автора заявки, голоса аккаунтов младше порога, голоса, поставленные до начала голосования, и одновременные 👍 с 👎 от одного человека не считаются. Если автор меняет в заявке репозиторий, голосование начинается заново.

## Жалобы и аварийная остановка

- **Жалобы.** Ссылка «Пожаловаться на приложение» есть на странице каждого приложения. Она открывает форму жалобы на языке сайта с уже указанным репозиторием. Когда открытых жалоб от разных аккаунтов старше 90 дней набирается `reports.toHide`, робот скрывает приложение со всех полок, из поиска и со страниц. Как только мейнтейнер закроет жалобы, приложение вернётся само.
- **Метка `blocked`.** Если поставить её на заявку приложения, робот снимет приложение при ближайшем запуске. Ставить метки могут только люди с правами на репозиторий маркета. Чтобы вернуть приложение, автор открывает заявку заново, и голосование проходит ещё раз.
- **Ежедневная перепроверка.** Робот раз в сутки проверяет опубликованные приложения. Если репозиторий удалён, закрыт, отправлен в архив или сменил лицензию на неоткрытую, приложение снимается, а в заявке появляется комментарий с причиной.

## Скачивание

Кнопка «Скачать» скачивает приложение одним нажатием, прямо из релизов проекта на GitHub.

1. **Робот разбирает файлы.** Раз в час он читает свежие релизы всех приложений и раскладывает файлы по именам (`scripts/downloads.mjs`). Система — по расширению: `.dmg` для macOS, `.msi` и `.exe` для Windows, `.AppImage` и `.deb` для Linux, `.apk` для Android. Процессор — по словам в имени: `arm64` и `aarch64`, `x64` и `x86_64`, `universal`. Контрольные суммы, подписи, серверные и консольные сборки отбрасываются, установщики идут раньше архивов. Результат с размером и SHA-256 каждого файла попадает в `catalog.json`.
2. **Страница выбирает файл.** Систему сообщает браузер, а Chrome и Edge сообщают ещё и процессор. Safari и Firefox его не сообщают, поэтому Mac получает универсальную сборку или сборку для Apple Silicon со ссылкой для Intel рядом, а Windows — x64.
3. **Кнопка говорит, что сделает.** «Скачать» скачивает файл, «Открыть» открывает веб-версию, «Сайт» и «GitHub» ведут на страницу загрузки проекта, если в его релизах нет готовых файлов. На странице приложения все файлы перечислены по системам, с размером и SHA-256.

`downloads.skip` в `rules.json` перечисляет репозитории, где в релизах лежит не само приложение, например консольная утилита фреймворка. `downloads.tags` оставляет только подходящие релизы, если репозиторий выпускает несколько продуктов. Ссылки на официальные страницы загрузки и веб-версии лежат в `LINKS` в `index.html`.

## Разведчик: новые приложения для каталога

Раз в неделю разведчик (`scripts/scout.mjs`) ищет на GitHub бесплатные приложения с открытым кодом, которых ещё нет в каталоге. Находка должна:
- иметь одну из тем из `scout.topics` и не меньше `scout.minStars` звёзд;
- быть под открытой лицензией из `repo.licenses`;
- иметь релиз не старше `scout.releaseWithinDays` дней;
- иметь готовые файлы для кнопки «Скачать»: их находит тот же разбор релизов, что и сама кнопка.

На каждую находку разведчик заводит задачу с меткой `scout`, где поля карточки уже заполнены. Название он собирает из имени репозитория, а категорию угадывает по темам и описанию.

1. **Проверьте поля.** Если нужно, поправьте их прямо в описании задачи.
2. **Поставьте метку `approved`.** При ближайшем проходе робот добавит приложение в его категорию на главной, ответит ссылкой на страницу приложения и закроет задачу. У одобренных находок нет пометки «Стороннее»: их выбрал мейнтейнер.
3. **Или закройте задачу**, если приложение не подходит. Разведчик больше его не предложит.

Одобренную находку снимает метка `blocked`, а ежедневная перепроверка действует на неё так же, как на приложения песочницы. Добавить приложение можно и вручную: завести задачу с теми же полями и поставить метки `scout` и `approved`.

## Страницы для поисковиков

Сайт — одна страница, но на GitHub Pages у каждого приложения есть ещё и свой адрес на каждом языке, например `ru/app/zed/` или `en/app/zed/`. Их собирает `scripts/build-site.mjs` при каждой публикации. У страницы свой заголовок и описание, ссылки `hreflang` на другие языки, разметка schema.org и текст о приложении: поисковик видит его даже без JavaScript. Скрипт страницы потом превращает его в обычный интерфейс. Ссылки внутри сайта ведут на эти адреса, корневой адрес сам выбирает язык посетителя, старые ссылки вида `#app-zed` продолжают работать.

`index.html` в репозитории остаётся одним файлом. Без сборки (файл с диска, `server.mjs`, превью) приложения открываются по `#app-zed`, как раньше.

Чтобы сайт быстрее попал в поиск, добавьте его в Google Search Console и Яндекс Вебмастер и отправьте туда `sitemap.xml`. Для подтверждения положите HTML-файл сервиса (`google….html`, `yandex_….html`) в корень репозитория, и сборка скопирует его в корень сайта. Или положите коды метатегов в переменные репозитория `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION` (**Settings → Secrets and variables → Actions → Variables**), и сборка добавит их на главную. Поисковики читают `robots.txt` только в корне домена, поэтому у сайта проекта его нет: карту сайта нужно отправить вручную.

## Для ИИ-агентов (MCP)

У VibeMarket есть свой MCP-сервер, `scripts/mcp.mjs`. Через него ИИ-агент вроде Claude Code, Claude Desktop или Cursor ищет по каталогу, подбирает бесплатную замену платным программам и скачивает нужный установщик для компьютера, на котором работает.

Claude Code:

```
claude mcp add vibemarket -- npx -y github:NickGBar/VibeMarket
```

Claude Desktop, Cursor и другие клиенты, в разделе `mcpServers` настроек:

```json
{ "mcpServers": { "vibemarket": { "command": "npx", "args": ["-y", "github:NickGBar/VibeMarket"] } } }
```

| Инструмент | Что делает |
|---|---|
| `find_alternative` | Бесплатные замены продукту: «Notion», «Photoshop», «Slack» |
| `search_apps` | Поиск по словам, категории, платформе или подборке |
| `get_app` | Описание, платформы, лицензия, ссылки и файлы с размерами и SHA-256 |
| `recent_updates` | Приложения со свежими релизами |
| `list_collections` | Подборки «Вместо …» и категории |
| `download_app` | Скачивает установщик для этого компьютера из релиза приложения на GitHub и сверяет SHA-256 |

Сервер работает у вас на компьютере, без зависимостей, нужен Node.js 22.9 или новее. Он читает с сайта `apps.json`: весь каталог в машиночитаемом виде, им может пользоваться кто угодно. `download_app` сохраняет файлы в папку «Загрузки», не перезаписывает существующие, принимает ссылки только на релизы самого приложения на GitHub и никогда не запускает установщики: устанавливает приложение человек.

### Приложения, которые работают с ИИ-агентом

У некоторых приложений есть свой MCP-сервер от авторов, и агент может работать прямо в них: семь приложений ArtCraft, draw.io, Excalidraw, Penpot, ComfyUI и Bitwarden. На их карточках стоит пометка «ИИ-агент», а на странице приложения написано, как подключить сервер к Claude Code, с кнопкой «Скопировать». Сторонние MCP-обёртки не в счёт: их код авторы приложения не проверяли. Список лежит в `AGENT` в `index.html`, попадает в `apps.json`, а `search_apps` с `agent: true` находит такие приложения.

## Языки

Сайт, формы на GitHub и ответы робота доступны на русском, английском, испанском и китайском.

**Сайт.** Язык переключается в шапке, выбор запоминается в браузере. При первом визите язык берётся из настроек браузера, а если он не из этих четырёх, сайт открывается на английском.

- Русский встроен в `index.html`: строки интерфейса лежат в блоке `<script type="application/json" id="i18n-ru">`, тексты каталога в данных `CATS`, `APPS` и `DETAILS`. Поэтому страница мгновенно открывается и работает даже как обычный файл.
- Остальные языки лежат в `locales/en.json`, `locales/es.json` и `locales/zh.json`, и страница загружает их при выборе. В каждом файле есть раздел `ui` с теми же ключами, что в русском блоке, `cats` с категориями и `apps` с описаниями, подробными текстами и подписями к скриншотам всех приложений каталога.
- Формы множественного числа задаются объектом с категориями `Intl.PluralRules`: для английского `one` и `other`, для испанского ещё `many`, для китайского достаточно `other`.
- Переводы вставляются в страницу как есть, поэтому HTML в них запрещён.

**Формы на GitHub.** У каждой формы есть вариант на каждом языке: `submit-app.yml` (русский), `submit-app-en.yml`, `submit-app-es.yml`, `submit-app-zh.yml` и такие же `report-app*.yml`. Сайт открывает вариант на языке посетителя. Поля во всех вариантах передаются по одинаковым id, а категория, цвет и платформы принимаются и как id (`work`, `green`, `web`), и как названия на любом из четырёх языков.

**Робот** узнаёт язык заявки по заголовкам полей и отвечает на нём же. Его тексты и заголовки форм лежат в `scripts/robot-i18n.mjs`.

Не переводятся только тексты приложений из песочницы: их пишут сами авторы.

Сверить переводы сайта с русским исходником:

```bash
npm run locales
```

Скрипт показывает недостающие и лишние ключи, неверные переменные вида `{name}`, пропущенные формы множественного числа, тексты приложений и HTML в переводах. В GitHub Actions он запускается перед каждой публикацией и выводит предупреждения, но публикацию не останавливает.

Чтобы добавить язык:

1. Скопируйте `locales/en.json` в `locales/<код>.json` и переведите. Добавьте код в `LANGS` и в список `<select id="lang">` в `index.html`.
2. Добавьте формы `submit-app-<код>.yml` и `report-app-<код>.yml`.
3. Добавьте заголовки полей в `FORM_LABELS` и тексты робота в `MESSAGES` в `scripts/robot-i18n.mjs`.

## Чего робот не умеет

- Проверять безопасность приложения: вредоносный код с хорошей лицензией пройдёт все правила. Поэтому на сайте стоит предупреждение, а для экстренных случаев есть метка `blocked`.
- Проверять, что приложение действительно бесплатное: это подтверждает автор.
- Полностью защитить голосование от фермы аккаунтов: порог возраста аккаунта затрудняет накрутку, но не исключает её.

Юридически за содержимое маркета отвечает владелец репозитория. Автоматика этого не меняет.

## Запуск на GitHub

Нужно сделать один раз:

1. Залить код в ветку `main` репозитория.
2. В репозитории открыть **Settings → Pages** и в **Source** выбрать **GitHub Actions**.
3. Открыть **Actions → Робот VibeMarket → Run workflow** или дождаться ближайшего запуска по расписанию.

Робот запускается раз в час, на каждое событие в Issues, на каждый push в `main` и вручную. Запуски идут по очереди. Если какой-то запуск пропадёт из очереди, ближайший проход по расписанию всё наверстает: робот заново просматривает все открытые заявки.

GitHub отключает расписание в публичном репозитории после 60 дней без активности. Робот коммитит `catalog.json`, когда меняются звёзды, поэтому в живом каталоге активность есть всегда.

Разведчик запускается по понедельникам и вручную: **Actions → Разведчик VibeMarket → Run workflow**.

### Безопасность робота

- Тексты заявок робот читает через API и никогда не передаёт в shell. В shell выполняется только `scripts/robot.mjs` из ветки `main`.
- Записи каталога робот собирает из проверенных полей, а не копирует файлы автора. Код из присланных репозиториев робот не запускает никогда.
- Служебные данные голосования робот хранит в своём комментарии и доверяет только комментариям `github-actions[bot]`. Подделать дату начала голосования нельзя.
- У workflow минимальные права, сторонние actions закреплены по хэшу коммита.
- Страница экранирует все данные из `catalog.json`, как недоверенные, и принимает ссылки на скачивание только на релизы того же репозитория на github.com.
- Описания репозиториев, которые разведчик кладёт в задачи, тоже недоверенные. Они попадают туда одной строкой, без HTML-комментариев и без упоминаний @человека: подсунуть лишнее поле формы или подделать метку разведчика нельзя.

## Локально

- Открыть `index.html` в браузере: страница работает и без сервера, на встроенном снимке каталога.
- `GH_TOKEN=$(gh auth token) npm run robot`: полный проход робота без записи в GitHub. Меняется только `catalog.json` на диске.
- `npm run stars`: обновить встроенный в `index.html` снимок звёзд. Он нужен, если `catalog.json` недоступен.
- `npm run locales`: сверить переводы с русским исходником.
- `npm test`: тесты робота, разведчика и MCP-сервера на поддельном GitHub API, сеть не нужна.
- `npm run mcp`: запустить MCP-сервер из репозитория, например чтобы подключить к агенту локальную копию.
- `GH_TOKEN=$(gh auth token) npm run scout`: показать, что разведчик нашёл бы сейчас, без создания задач.
- `npm run site`: собрать сайт в `_site/` так, как его получает GitHub Pages.

## Необязательный сервер: вход через GitHub

Для маркета сервер не нужен. Но если запустить `server.mjs`, на сайте появятся:

- вход через GitHub, аватар и логин в шапке;
- кнопка Star на странице приложения, которая ставит и снимает звезду прямо на GitHub;
- полка «Ваши звёзды» и отметки на карточках;
- число звёзд, обновлённое через GitHub API от имени пользователя.

Зависимостей нет, нужен Node.js 22.9 или новее.

```bash
npm start
```

### Настройка

1. Создайте GitHub App: https://github.com/settings/apps/new
   - **Homepage URL**: `http://localhost:3000`.
   - **Callback URL**: `http://localhost:3000/auth/callback`.
   - **Webhook**: снимите галочку **Active**.
   - **Permissions → Account permissions → Starring**: `Read and write`. Других прав не нужно.
   - **Where can this GitHub App be installed?** `Only on this account` для проверки у себя, `Any account`, чтобы входить могли другие люди.
2. Скопируйте **Client ID** и создайте **client secret**.
3. Создайте `.env` по образцу и вставьте туда оба значения:

   ```bash
   cp .env.example .env
   ```

GitHub App выбран вместо OAuth App, потому что OAuth App для звёзд запросил бы право на запись во все публичные репозитории пользователя (`public_repo`).

Как устроен сервер:

- Токен GitHub хранится только в памяти сервера, браузер получает cookie сессии с флагами `HttpOnly` и `SameSite=Lax`. Вход защищён `state` и PKCE, при выходе токен отзывается.
- Страница по-прежнему не обращается к сторонним сайтам, кроме GitHub API в форме заявки. Политика CSP разрешает выполнять только её собственный скрипт.
- Звёзды можно ставить только приложениям из каталога и песочницы.
- Сессии хранятся в памяти, поэтому после перезапуска нужно войти заново.
- Для работы на своём домене нужен HTTPS. Укажите `BASE_URL=https://ваш-домен` и поменяйте адреса в настройках GitHub App.
